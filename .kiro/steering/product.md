# プロダクト概要

news.hako.tokyo は、複数の日本語ニュース／技術情報源から記事を自動収集し、1 つのページに集約して表示する**個人向けニュースアグリゲーター**である。毎朝 7:00 (JST) に GitHub Actions のジョブが最新記事を取得し、静的サイト（Vercel デプロイ）を自動更新する。利用者は作者（umatoma）個人を想定し、認証・共有・公開 API は持たない。

## コア機能

- **複数ソース収集**: Zenn・はてなブックマーク・Google ニュース・Togetter から記事を取得（RSS とスクレイピングの併用）
- **定期自動収集**: GitHub Actions の cron（毎朝 7:00 JST）で収集 → Markdown 書き出し → main へ自動コミット → Vercel 再デプロイ
- **単一ページ表示**: 直近期間の記事を新しい順に一覧表示。ソースバッジ・公開時刻・外部リンクを付与
- **Git ベースの永続化**: 全記事を Markdown（frontmatter 付き）として `content/` に保存し、データベースなしで履歴・追跡を可能にする
- **重複排除**: URL を基準に再収集時の重複を排除し、同一記事を二重保存しない

## 想定ユースケース

朝の情報トリアージ。散在する技術／ニュース情報源を 1 ページに集約し、毎朝の情報収集時間を短縮する。収集データを「検索・追跡可能な個人記録」として Git に残すことも目的に含む。

## 価値提案

- **最小インフラ + Git ネイティブ設計**: データベース・バックエンド API・認証層を持たず、静的サイト + 定期ジョブのみで完結。コンテンツは Git でバージョン管理され、履歴監査・オフライン参照が可能
- **設定の一元化**: 収集ルールは設定ファイル（`config/sources.ts`）に集約され、ソースの追加・変更が容易かつ監査可能
- **自動化ファースト**: 初期設定を除き手動トリガー不要。収集・重複排除・コミット・デプロイを毎日の cron が自動実行する

一般的な RSS リーダー（Feedly 等）が持つ検索・共有・スマートフィードを意図的に省き、**透明性・監査可能性・運用コストの低さ**に価値を置く。
