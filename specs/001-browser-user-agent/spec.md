# Feature Specification: 収集時の User-Agent をブラウザ偽装値に調整

**Feature Branch**: `001-browser-user-agent`

**Created**: 2026-05-30

**Status**: Draft

**Input**: User description: "ユーザエージェントを調整したい（ブラウザ偽装したい / 全収集元に一括適用）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - bot 判定で弾かれる収集元から記事を取得できる (Priority: P1)

記事収集バッチが外部サイト（Zenn / Hatena / Google News / Togetter）へHTTPリクエストを送る際、
現在は collector 名乗りの User-Agent を送っているため、一部サイトが bot として
アクセスを拒否（または空・エラー応答を返す）し、記事が取得できないことがある。
収集処理が一般的な実在ブラウザと同等の User-Agent を送ることで、これらのサイトからも
通常どおりレスポンスを受け取り、記事を取得・蓄積できるようにする。

**Why this priority**: これが本機能の唯一かつ中心的な目的。実装しなければ収集自体が
成立しない収集元が存在するため、最優先（P1）。この1ストーリーだけで MVP として成立する。

**Independent Test**: 収集バッチを全収集元に対して実行し、bot 判定で弾かれていた収集元から
HTTP 200 と本文（RSS XML / HTML）が返り、記事が新規に蓄積されることを確認できれば
単独でテスト可能。

**Acceptance Scenarios**:

1. **Given** 収集対象サイトが実在ブラウザ相当の User-Agent のみを受け付ける状態、**When** 収集バッチが当該サイトへリクエストを送る、**Then** HTTP 200 と本文が返り、記事が解析・蓄積される
2. **Given** 全4収集元（Zenn / Hatena / Google News / Togetter）、**When** 収集バッチを実行する、**Then** すべての収集元へのリクエストが同一のブラウザ偽装 User-Agent を送信する
3. **Given** これまで正常に取得できていた収集元、**When** User-Agent 変更後に収集バッチを実行する、**Then** 従来どおり記事を取得でき、リグレッションが発生しない

### Edge Cases

- 収集元サイトがブラウザ偽装 User-Agent でもなお bot 判定する場合、収集処理は従来どおりの
  エラーハンドリング（失敗した収集元をスキップし、他の収集元の処理を継続）で振る舞う。
  本機能はエラーハンドリングの仕組み自体は変更しない。
- 個別リクエストで呼び出し側が明示的に User-Agent を指定した場合は、その指定が優先される
  （既存の上書き挙動を維持する）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 収集処理は、外部サイトへの全HTTPリクエストにおいて、一般的な実在ブラウザと
  同等の User-Agent 文字列を送信しなければならない (MUST)。
- **FR-002**: ブラウザ偽装 User-Agent は、全収集元（Zenn / Hatena / Google News / Togetter）に
  対して一括で同一の値を適用しなければならない (MUST)。収集元ごとに異なる値は用いない。
- **FR-003**: 呼び出し側がリクエスト単位で User-Agent を明示指定した場合、その指定値が
  既定のブラウザ偽装値より優先されなければならない (MUST)（既存の上書き挙動を維持）。
- **FR-004**: User-Agent 変更後も、これまで正常に取得できていた収集元からの記事取得が
  継続して成功しなければならない (MUST)。

### Key Entities

- **User-Agent 既定値**: 全収集元の外部リクエストに付与される、実在ブラウザ相当の
  HTTP User-Agent 文字列。収集処理全体で単一の値として共有される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 収集バッチ実行時、全4収集元へのリクエストが同一のブラウザ偽装 User-Agent を
  送信する（送信ヘッダーの検証で 4/4 が一致）。
- **SC-002**: bot 判定で記事を取得できていなかった収集元から、変更後は記事を取得・蓄積できる
  （該当収集元の取得記事数が 0 件から 1 件以上に増加する）。
- **SC-003**: 変更前に正常取得できていた収集元の取得成功率が、変更後も維持される
  （リグレッションによる取得失敗が 0 件）。

## Assumptions

- 「ブラウザ偽装」とは、実在する一般的なデスクトップブラウザ（例: Chrome）が送信する
  形式の User-Agent 文字列を用いることを指す。具体的なブラウザ・バージョンの選定は
  実装フェーズ（`/speckit-plan`）で確定する。
- User-Agent は現状ハードコードされた単一の既定値であり、本機能でもハードコードされた
  単一の既定値として扱う（環境変数・設定ファイルによる外部化はスコープ外）。
- 収集元ごとに User-Agent を出し分ける要件はない（ユーザー確認により「全収集元に一括」と確定）。
- 本機能は User-Agent 文字列の値の変更が対象であり、リトライ・レート制限・robots.txt 遵守等の
  アクセスポリシー全般の見直しはスコープ外。
- 既存の HTTP リクエスト共通化（全収集元が単一の HTTP クライアント経由でリクエストする構造）は
  維持し、再利用する。
